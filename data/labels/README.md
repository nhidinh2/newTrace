# Labels

| File | Purpose | Who writes it |
| --- | --- | --- |
| `fixture_story_labels.csv` | Ground-truth story grouping for the **synthetic** committed fixtures. Generated by `scripts/make_fixtures.py`. | generated |
| `story_pairs.template.csv` | Schema plus three synthetic examples for article-pair labelling. | committed template |
| `story_pairs.queue.csv` | Borderline pairs sampled near the clustering threshold, produced by `make labels`. | generated |
| `story_pairs.csv` | **Your** reviewed labels. Not committed by default. | project owner |
| `retrieval_judgments.template.csv` | Schema for query/article relevance judgments. | committed template |
| `retrieval_judgments.csv` | **Your** reviewed judgments. Not committed by default. | project owner |

## How to label

1. `make demo` (or a live ingestion run) so there are articles to compare.
2. `make labels` writes `story_pairs.queue.csv`: the pairs whose clustering score
   sits closest to the decision threshold, i.e. the ones where a human judgement
   actually changes the outcome.
3. Fill in `same_story` (`1` or `0`), `reviewer` and `notes`.
4. Save the completed file as `story_pairs.csv`.

`scripts/run_experiments.py` prefers reviewed labels over the synthetic fixture
labels, and prefers both over silver labels derived from the system's own
clustering. The report records which source was used.

**Do not** copy the synthetic examples into a real label file: they exist to
document the schema, not to stand in for human review.
